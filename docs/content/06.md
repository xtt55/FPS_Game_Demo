## 本课要解决什么

1. 把移动输入**缓存到变量**（Move X / Move Y），松开键时清零。
2. 用 `Want to Run` / `Want to Aim` 记录跑步键、瞄准键的**输入意图**。
3. 用**枚举** `EPlayerState` + 函数 `UpdatePlayerState` 统一算出 Idle / Walk / Run / Aim。
4. 按状态改 `Max Walk Speed`（本课不做动画，动画第 07 课接）。

---

## 一、变量：缓存输入

### 1. Move X / Move Y

在 `IA_Move` 里把 Action Value 拆成 X/Y 后**提升为变量** `Move X`、`Move Y`：

- **Triggered**：SET 两变量（供移动逻辑和动画系统读取）
- **Completed**：再 SET 两变量为 **0**

**为什么必须 Completed 清零？** Triggered 只在键按住时跑。松开后 Triggered 不再执行，变量会**卡在松开前的值**（例如一直在「前进」）。Completed 在松开时执行，手动写成 0，状态机才能看到「没在按」。

轴约定：**Move X = W/S（前后）**，**Move Y = A/D（左右）**。

### 2. Want to Run / Want to Aim

- `IA_Run`（左 Ctrl）：Triggered → `Want to Run = true`；Completed → `false`。
- `IA_Aim`（右键）：同理写 `Want to Aim`。

注意命名：这是「**想不想**跑 / 瞄」（输入意图），**还不等于**最终状态（还要过优先级判断）。

## 三、函数 UpdatePlayerState（状态中枢）

![UpdatePlayerState 完整图](assets/img/l06-updateplayerstate-graph.png)

### 节点逐个解释

| 节点 | 解释 |
|:---|:---|
| **UpdatePlayerState 入口**（紫色） | 图最左边的起点，代表「这个函数开始执行」。没有输入，只有一条白色执行线往外走 |
| **第一个 Branch**（流程控制） | 菱形判断：一个红色布尔输入（条件），两个白色执行输出 True / False。本图条件接 **Want to Aim**，True 走 Aim，False 往下走 |
| **Set E Player State**（变量赋值） | 把一个枚举值（Aim/Run/Walk/Idle）写进 E Player State 变量。一条白线进、一条出（赋值完继续），数据输入脚接具体的枚举常量 |
| **Want to Aim / Want to Run**（Getter） | 蓝色小节点，输出红色布尔细线，把当前 bool 变量的值喂给 Branch 当条件 |
| **第二个 Branch**（判断 Move X > 0） | 条件不是直接接变量，而是接比较节点的输出 |
| **`>` 比较节点**（纯函数，无白线） | 绿色节点，吃两个绿色 float（左边 Move X，右边常量 0.0），吐出红色布尔线给 Branch。没有白色执行线 = **纯函数**，不消耗执行流，只在需要值时计算 |
| **第三个 Branch**（再判断 Want to Run） | 在 Move X > 0 的 True 分支里，判断要不要跑 |
| **Character Movement → Velocity → Vector Length** | Character Movement：深蓝对象脚（角色移动组件），从左侧蓝图树拉出；Velocity：从它身上取出的蓝色向量脚（当前速度向量）；Vector Length：纯函数，把蓝色向量变成绿色 float（速度大小/模长） |
| **第四个 Branch**（判断 Velocity.Length > 0） | 在 Move X == 0 的 False 分支里，用「实际速度是否还在动」兜底判断是否 Walk |

### 工作流（优先级从高到低）

```
1. Want to Aim == true                    → Aim（瞄准压过一切）
2. Move X > 0（按住 W）且 Want to Run      → Run
3. Move X > 0（按住 W）且没按跑            → Walk
4. Move X == 0 但 Velocity.Length > 0      → Walk（A/D/S 或减速残留）
5. 全部不满足                              → Idle
```

> 设计说明：**只用 Move X 判断跑步**——多数 FPS 只允许「向前跑」，没有左右跑动画时更稳妥，A/D/S 不进 Run。瞄准中按跑步键仍应是 Aim（第 1 条优先）。

## 四、函数 UpdateMoveSpeed（按状态改速度）

`E Player State` → **Select** 节点 → `Set Max Walk Speed`（Target：Character Movement）。

参考值（可微调）：

| 状态 | Max Walk Speed |
|:---|:---|
| Idle | 400（防怪 bug，不必 0） |
| Walk | 400 |
| Run | 600 |
| Aim | 265 |

在 **Event Tick** 里（接在已有 Arm 旋转逻辑之后）：先调 `UpdatePlayerState`，再调 `UpdateMoveSpeed`。

## 易错点速查

1. 忘了 Walk 的 **Completed → 置 0** → 松键仍像在走/能误触发 Run。
2. `E Player State` 类型要选**枚举**，别建成布尔。
3. 只按跑步键不能跑：必须 **W + 跑步键**（Move X > 0 且 Want to Run）。
4. 瞄准中按跑步键仍应是 Aim，不是 Run。
5. Velocity 的中文「速度」实为**速度向量**；用**向量长度（Vector Length）**判断是否还在动。
