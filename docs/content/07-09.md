## 一、整体结构（先看全貌）

动画系统分两侧，每侧一条链路：

```
BP_FPS_Player（角色蓝图）
  │  Event Graph 每帧同步变量（Move X / Move Y / E Player State / Character Movement）
  ▼
ABP_FPSPlayer（动画蓝图）
  │  AnimGraph：状态机算姿势
  ▼
Arm / Gun 网格体（动画模式 = 使用动画蓝图）
```

最终状态机 `Basic` 里共 5 个状态：

```
        ┌──────────► Run ◄──────────┐
        │            │              │
Entry ──► Move ──► ToAim ──► Aim    │
        ▲            ▲    │         │
        │            │    ▼         │
        └──── ToIdle ◄────┘         │
```

- **Move**：播混合空间（八方向行走 + Idle）
- **Run**：播 Sprint 序列
- **Aim**：按实际速度在 ADS Idle / ADS Walk 之间混合
- **ToAim / ToIdle**：进瞄 / 出瞄的过渡动画状态

## 三、Event Graph：同步角色变量

### 作用

把玩家角色 `BP_FPS_Player` 身上的数据「同步」到动画蓝图自己的变量里，AnimGraph 才能根据这些数据选动画。

![ABP_FPSPlayer Event Graph](assets/img/l07-abp-eventgraph-sync.png)

### 节点逐个解释

| 节点 | 解释 |
|:---|:---|
| **Event Blueprint Update Animation**（红色事件） | 动画蓝图每帧触发一次，相当于动画版的 Tick。输出：白色执行线 + Delta Time X（绿色 float，本帧间隔时间，暂时没用上，做时间相关插值/混合时会用到） |
| **Try Get Pawn Owner**（绿色纯函数） | 获取「拥有这个动画蓝图的 Pawn」。Target [self] 表示调用者是动画蓝图自己；Return Value（深蓝对象线）返回通用 Pawn。为什么是 Try？因为动画蓝图理论上可以挂到不同角色上，不保证有 Pawn |
| **Cast To BP_FPS_Player** | 把通用 Pawn 安全地转成自定义角色类型。Object 脚接 Try Get Pawn Owner 的返回值；输出 As BP FPS Player（深蓝线）+ Cast Failed（白线，没接，可接 Print String 调试）。只有转换成功后，才能读角色的自定义变量 |
| **四个变量 Getter**（Move X / Move Y / E Player State / Character Movement） | 从 As BP FPS Player 身上读：Move X（绿线，前后移动输入）、Move Y（绿线，左右移动输入）、E Player State（枚举线）、Character Movement（角色移动组件）。这四个小节点左边有 Target 脚，被蓝线连到 As BP FPS Player |
| **四个 SET 节点** | 把读到的值写进**动画蓝图自己**的同名变量。做法：把变量拖出后点「提升为变量（Promote To Variable）」。**Target 应该是动画蓝图自己（self），不要连到 BP_FPS_Player**。执行顺序从左到右依次设置 |

### 工作流

```
每帧更新动画 → 拿到当前控制的 Pawn → 确认它是 BP_FPS_Player
  → 把 Move X、Move Y、E Player State、Character Movement
  → 复制到动画蓝图自己的同名变量里
```

这样动画蓝图就知道：玩家有没有移动、移动方向、当前状态（Idle/Walk/Run/Aim），从而播对应的动画。

> **易错**：Cast 节点的**执行针一定要接上**。漏接时 AnimBP 里轴一直是 0，看起来「前后左右没动画」。

### 枪械侧 ABP_VIRTUL

与人物同理，可以直接从 `ABP_FPSPlayer` 拷贝节点。注意：拷贝的话变量不会自动创建，对引脚右键「创建变量」。

## 五、状态机骨架：Move 态

**State Machine 节点**（命名为 Basic）：一个「动画状态机」容器，内部放多个状态 + 转换规则，对外输出最终 Pose。**Output Pose** 是 AnimGraph 的最终出口，连进去的 Pose 就是角色实际播放的动画。

连线：State Machine → Output Pose，意思是「动画蓝图最终输出状态机算出来的结果」。

双击状态机进入内部画布。**Entry（入口节点）**是状态机的起点，从 Entry 拖白线连到 **Move** 状态：表示默认进入 Move。只有一个状态时，右上角会提示 `Move 100.0%`（满权重激活）。

### 3. Aim 态：按速度混合 ADS Idle / ADS Walk

![Aim 节点配置](assets/img/l09-aim-state-config.png)

Aim 状态内部不播「一个」动画，而是**根据角色实际移动速度，在 Idle（稳瞄）和 Walk（走瞄）之间平滑切换**。这里用 **Blend Poses by Bone（按骨骼混合）** 节点做过渡，不会生硬跳切。

#### 节点逐个解释（数据流从底到顶）

| 节点 | 解释 |
|:---|:---|
| **Character Movement**（深蓝，变量 Getter） | 从「我的变量」面板拖出的移动组件对象引用，后续从它身上取速度 |
| **Velocity**（深蓝针脚） | 从组件读当前帧的**速度向量（Vector）**。Target 脚接 Character Movement；输出一根蓝色细线，代表 (X, Y, Z) 三轴速度 |
| **Vector Length**（绿色纯函数） | 把蓝色速度向量变成绿色标量 float（模长，忽略方向）。站着不动 ≈ 0；走路 ≈ 200~400；跑步 ≈ 600+。无白色执行线 = 纯函数 |
| **`> 0.0` 比较** | 判断「速度是否 > 0」（在移动为 true），输出红色布尔线 |
| **Blend Poses by Bone**（核心混合节点） | True Pose 接 Walk（在动时播）、False Pose 接 Idle（静止时播）、True/False Blend Time 各 **0.1 秒**、Active Value 接「速度 > 0」的布尔。「by Bone」表示可指定某些骨骼用不同权重混合（默认全骨骼统一），高级用法可做「上身瞄准、下身走路」分层 |
| **两个 Animation Player**（ADS Walk / ADS Idle） | 直接引用动画资产，分别连 True / False Pose。**记得勾选循环动画** |
| **Output Animation Pose** | 这个状态的最终出口 |

#### 数据流全景

```
Character Movement (组件)
    ↓ (深蓝对象线)
Velocity (取速度向量)
    ↓ (蓝色向量线)
Vector Length (向量 → 标量)
    ↓ (绿色 float 线)
[> 0.0] 比较
    ↓ (红色 bool 线)
Blend Poses by Bone.Active Value
    ├─ True  → Walk 动画 → True Pose
    └─ False → Idle 动画 → False Pose
    ↓ (混合后的姿势)
Output Animation Pose → 屏幕上的角色
```

#### 与 Event Graph 的分工（重要）

| 位置 | 做什么 | 驱动数据 |
|:---|:---|:---|
| **Event Graph**（第 06 课） | 每帧算 `E Player State` 枚举 | **输入意图**（玩家是否按键：Move X/Y + Want to Run/Aim） |
| **AnimGraph**（本图） | 根据**实际速度**混合 Idle/Walk | **实际物理结果**（Character Movement.Velocity 长度） |

两者不完全一致，但这正是正确的分工：

- 按了 W 但被墙挡住 → 输入有、速度 = 0 → 逻辑说 Walk，视觉播 Idle（✅ 对）
- 松开按键但惯性滑行 → 输入无、速度 > 0 → 逻辑说 Idle，视觉播 Walk（✅ 对）

**结论**：Event Graph 管逻辑状态，AnimGraph 管视觉表现，各管各的。

## 七、状态之间的转换规则

双击两个状态之间的小箭头，进入**转换规则（Transition Rule）**编辑——它是状态机里连在两个状态之间的那条线，条件满足时角色才从源状态切到目标状态，最终结果接 **Can Enter Transition**。

状态间的连线总览（Move ↔ Run 双向；Move → ToAim → Aim → ToIdle → Move 主环路；ToAim ↔ ToIdle 两条打断边）：

![状态机布局](assets/img/l09-statemachine-toaim-toidle.png)

### 全部转换条件一览

| 边 | 条件 | 含义 |
|:---|:---|:---|
| Move → Run | `E Player State` **== Run** | 进入跑步 |
| Run → Move | `E Player State` **!= Run** | 只要不是跑，就回 Move |
| Move → ToAim | `E Player State` **== Aim** | 按下瞄准，开始进瞄过渡 |
| ToAim → Aim | 剩余动画时间 **< 0.4** | 过渡快播完才进正式瞄准 |
| Aim → ToIdle | `E Player State` **!= Aim** | 松开瞄准，开始出瞄过渡 |
| ToIdle → Move | 剩余动画时间 **< 0.4** **OR** `== Run` | 过渡播完回 Move；跑步则立刻切 |
| ToAim → ToIdle | `E Player State` **!= Aim** | 打断边：进瞄中途松键，立刻往回 |
| ToIdle → ToAim | `E Player State` **== Aim** | 打断边：出瞄中途再按，立刻再进瞄 |

**配置要点**：

- 枚举比较要搜「等于」时选**等于（枚举）**，不要用数值的等于；搜「不等于」要用英文输入法敲 `!`，中文 `！` 搜不到
- 「剩余动画时间」节点是 **Get Relevant Anim Time Remaining**（剩余秒数）；0.4 可微调，更大则更早切走

### 详解：ToIdle → Move 为什么要 OR Run

这条边的完整逻辑：

```
允许从 ToIdle 切到 Move = (ToIdle 动画剩余时间 < 0.4)  或  (E Player State == Run)
```

| 节点 | 解释 |
|:---|:---|
| **Get Relevant Anim Time Remaining (ToIdle)**（绿色纯函数） | 获取源状态（ToIdle）正在播的动画还剩多少时间。括号里的 `(ToIdle)` 指定检测的是「源状态」动画的进度 |
| **`< 0.4` 比较**（红色布尔输出） | 过渡动画快播完才允许切走，防止动画才播个开头就被打断 |
| **E Player State `== Run`**（枚举判断） | 玩家当前是否在跑 |
| **OR**（布尔或） | 两个条件满足其一就放行 |

**为什么要 OR Run**：松右键马上按跑步键时，角色状态早已是 Run，但动画会卡在 ToIdle 播完才走。加上 OR Run 后，跑步优先级高，强制立刻切换，不等动画——松瞄立刻 sprint 不卡。

### 详解：两条打断边

若没有 ToAim ↔ ToIdle 这两条横边，快速按下/松开右键仍会把整段过渡播完，手感「不跟手」。有了它们，进瞄中途松键立刻往回，出瞄中途再按立刻再进瞄。

### 补充：Move ↔ Aim 的简版直切（已被过渡方案替代）

加过渡状态之前，Aim 是和 Move 直接双向连线的（`== Aim` / `!= Aim`），靠引擎按混合时长硬插值过渡——拉长到 0.5 秒会又慢又僵，所以最终改成了上面的 ToAim/ToIdle 方案。这两张图仅作对照记录：

## 易错点速查

1. **Update Animation 未接 Cast 执行针** → 混合空间始终中心 Idle。
2. Move X/Y 接混合空间时接反 → 前后与左右对调。
3. 用**数值等于**比较枚举 → 应用「等于/不等于（枚举）」；中文输入法敲 `！` 搜不到「不等于」。
4. 搜 `run` 找不到动画 → 搜 **`sprint`**。
5. Run / ADS 序列忘勾**循环动画** → 播一次就停；ToAim/ToIdle **勾了循环** → 永远进不了 Aim / 回不了 Move。
6. 只做手臂、漏枪；或两边平滑时间/过渡曲线不一致 → 穿模。
7. Event Graph 没同步 Character Movement → Aim 里的 Blend 布尔一直假，只会 Idle 瞄。
8. 忘了 ToIdle→Move 的 **OR Run** → 松瞄再 sprint 有明显延迟。
