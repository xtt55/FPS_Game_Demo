# （上）混合空间 + 动画蓝图骨架

## 本课要解决什么

1. 建手臂 / 枪两套**混合空间（BS）+ 动画蓝图（ABP）**。
2. 每帧从 `BP_FPS_Player` **同步** `Move X` / `Move Y` / `E Player State` / `Character Movement`。
3. AnimGraph：状态机 → Move 态播混合空间；**Move X→Forward，Move Y→Right**。
4. 在角色上把 Arm / Gun 的动画模式改成**使用动画蓝图**。

本课只做**走路四向 + Idle**；跑、瞄准在后面两课。

## 三、ABP_FPSPlayer 的 Event Graph：同步角色变量

![ABP_FPSPlayer Event Graph](assets/img/l07-abp-eventgraph-sync.png)

### 作用

把玩家角色 `BP_FPS_Player` 身上的数据「同步」到动画蓝图自己的变量里，这样 AnimGraph（动画图）才能根据这些数据选动画。

### 节点逐个解释

| 节点 | 解释 |
|:---|:---|
| **Event Blueprint Update Animation**（红色事件） | 动画蓝图每帧触发一次，相当于动画版的 Tick。输出：白色执行线 + Delta Time X（绿色 float，本帧间隔时间，暂时没用上，做时间相关插值/混合时会用到） |
| **Try Get Pawn Owner**（绿色纯函数） | 获取「拥有这个动画蓝图的 Pawn」。Target [self] 表示调用者是动画蓝图自己；Return Value（深蓝对象线）返回通用 Pawn。为什么是 Try？因为动画蓝图理论上可以挂到不同角色上，不保证有 Pawn |
| **Cast To BP_FPS_Player** | 把通用 Pawn 安全地转成自定义角色类型。Object 脚接 Try Get Pawn Owner 的返回值；输出 As BP FPS Player（深蓝线）+ Cast Failed（白线，没接，可接 Print String 调试）。只有转换成功后，才能读角色的自定义变量 |
| **四个变量 Getter**（Move X / Move Y / E Player State / Character Movement） | 从 As BP FPS Player 身上读：Move X（绿线，前后移动输入）、Move Y（绿线，左右移动输入）、E Player State（枚举线）、Character Movement（角色移动组件）。这四个小节点左边有 Target 脚，被蓝线连到 As BP FPS Player |
| **四个 SET 节点** | 把读到的值写进**动画蓝图自己**的同名变量。做法：把变量拖出后点「提升为变量（Promote To Variable）」。**Target 应该是动画蓝图自己（self），不要连到 BP_FPS_Player**。执行顺序从左到右依次设置 |

### 工作流

```
每帧更新动画 → 拿到当前控制的 Pawn → 确认它是 BP_FPS_Player
  → 把 Move X、Move Y、E Player State、Character Movement
  → 复制到动画蓝图自己的同名变量里
```

这样动画蓝图就知道：玩家有没有移动、移动方向、当前状态（Idle/Walk/Run/Aim），从而播对应的动画。

> **易错**：Cast 节点的**执行针一定要接上**。漏接时 AnimBP 里轴一直是 0，看起来「前后左右没动画」。

## 四、AnimGraph：状态机 + Move 态

**作用**：角色按 W/S 时 Move X 变，A/D 时 Move Y 变，混合空间就在这两轴上混合 Idle/前走/后走/左走/右走等动画，实现八方向移动。

### 第一步：新建状态机

**State Machine 节点**（图中叫 Basic State Machine）：一个「动画状态机」容器，内部放多个状态 + 转换规则，对外输出最终 Pose。**Output Pose** 是 AnimGraph 的最终出口，连进去的 Pose 就是角色实际播放的动画。

连线：State Machine → Output Pose，意思是「动画蓝图最终输出状态机算出来的结果」。

![状态机连 Output Pose](assets/img/l07-animgraph-statemachine.png)

### 第二步：添加 Move 状态

双击 State Machine 进入内部画布。**Entry（入口节点）**是状态机的起点，游戏一开始从这里出发。从 Entry 拖白线连到一个 **Move** 状态：表示默认进入 Move 状态。

右上角提示 `Move 100.0%`：说明当前这个状态一直满权重激活（因为现在只有它一个状态）。

![Entry 连 Move](assets/img/l07-statemachine-entry-move.png)

### 第三步：在 Move 里放混合空间

双击 Move 状态进去，里面是另一个小 AnimGraph。右键拖出 **BlendSpace Player**，选资产 `BS_FPSPlayer`：

- 变量 **Move Y** 接混合空间的 **Right**（左右轴）
- 变量 **Move X** 接 **Forward**（前后轴）
- BlendSpace 输出 → **Output Animation Pose**（这个状态自己的 Pose 出口）

![Move 内 BlendSpace](assets/img/l07-move-state-blendspace.png)

### 第四步：在 Move 节点内部点击编译

![编译](assets/img/l07-move-state-compile.png)

## 五、挂到网格体

回到 `BP_FPS_Player`，选中 **Arm**（手臂骨骼网格体）：

# （中）加 Run 状态

承接（上）的 Move 态 + 混合空间；本课只补**奔跑（Run）**状态与过渡。瞄准留给（下）。

## 本课要解决什么

1. 在状态机里加 **Run** 态，与 Move **一去一回**两条过渡线。
2. 过渡条件用第 06 课同步来的 `E Player State`：`== Run` / `!= Run`（**枚举比较**）。
3. Run 态播 **Sprint** 序列，并勾**循环动画**。

## 第五步：添加 Run 节点，和 Move 节点拉出双向的线

![添加 Run 双向连线](assets/img/l08-add-run-state.png)

## 第六步：双向线箭头配置（转换规则）

双击两个状态之间的小箭头，进入**转换规则（Transition Rule）**编辑——它是状态机里连在两个状态之间的那条线，条件满足时角色才从源状态切到目标状态。

**从 Move 向 Run**：当 `E Player State == Run` 时，调用跑步动画。注意搜「等于」时要选**等于（枚举）**，不要用数值的等于。

![Move→Run 条件](assets/img/l08-transition-move-to-run.png)

**从 Run 向 Move**：当 `E Player State != Run` 时，回到 Move（Walk / Idle / Aim 都走这条回来）。搜「不等于」要用英文输入法敲 `!`，中文 `！` 搜不到。

![Run→Move 条件](assets/img/l08-transition-run-to-move.png)

## 第七步：Run 节点配置

进入 Run 状态，资产浏览器搜 **`sprint`**（不要搜 `run`——序列名是 Sprint），拉出对应动画接输出姿势。**注意检查循环播放按钮是否勾选**，最后点击编译。

![Run 节点动画](assets/img/l08-run-state-animation.png)

> 枪械 `ABP_VIRTUL` 的状态机做同样一套：加 Run、双向过渡、同样的枚举条件、Weapon Sprint + 循环。
>
> 进阶：若切跑/停跑太「硬」，可在状态机里框选两条过渡，Details → 混合设置调**混合时长**（课例 0.3 秒）；手臂与枪要用同一套时长和曲线，否则穿模。

# （下）加 Aim 状态与过渡动画

承接 Move / Run；本课做**瞄准（Aim）**：先简版直切，再加 **ToAim / ToIdle** 过渡动画，并处理狂按右键、松瞄立刻奔跑。

## 第八步（方法一）：Aim 节点与 Move 直切双向线

添加 Aim 节点，和 Move 节点拉出双向的线——先用引擎自行合成的过渡（混合时长硬插值）。

**从 Move 向 Aim**：`E Player State == Aim` 时调用瞄准动画。

![Move→Aim](assets/img/l09-transition-move-to-aim.png)

**从 Aim 向 Move**：`E Player State != Aim` 时回 Move。

![Aim→Move](assets/img/l09-transition-aim-to-move.png)

## 第九步（方法二）：ToAim / ToIdle 过渡动画节点

引擎靠混合时长硬插值，拉长会又慢又僵。资源里已有 `Idle_to_ADS`（站立→瞄准）和 `ADS_to_Idle`（瞄准→站立）过渡序列，比自动合成自然得多。于是：**删掉 Move↔Aim 直接边**，在 Move 和 Aim 之间插入两个过渡状态，连上双向线：

```
Move ──► ToAim ──► Aim
 ▲                  │
 └──── ToIdle ◄─────┘
```

![ToAim/ToIdle 布局](assets/img/l09-statemachine-toaim-toidle.png)

**ToAim 节点配置**：播 `Idle_to_ADS`，**不要勾循环**（过渡动画只播一次）。

![ToAim 节点](assets/img/l09-toaim-state.png)

**ToIdle 节点配置**：播 `ADS_to_Idle`，同样不勾循环。

![ToIdle 节点](assets/img/l09-toidle-state.png)

## 转换规则逐条配置

**Move → ToAim**：`E Player State == Aim`。

![Move→ToAim](assets/img/l09-transition-move-toaim.png)

**ToAim → Aim**：`Get Relevant Anim Time Remaining (ToAim) < 0.4`——过渡动画快播完（剩余不足 0.4 秒）才切入正式 Aim，保证过渡播完不跳切。

![ToAim→Aim](assets/img/l09-transition-toaim-aim.png)

**Aim → ToIdle**：`E Player State != Aim`。

![Aim→ToIdle](assets/img/l09-transition-aim-toidle.png)

**ToIdle → Move**：详见下方「转换规则详解」。

![ToIdle→Move](assets/img/l09-transition-toidle-move.png)

**ToAim → ToIdle**（打断边）：`E Player State != Aim`——进瞄中途松键，立刻往回，不用把整段过渡播完。

![ToAim→ToIdle](assets/img/l09-transition-toaim-toidle.png)

**ToIdle → ToAim**（打断边）：`E Player State == Aim`——出瞄中途再按，立刻再进瞄。

![ToIdle→ToAim](assets/img/l09-transition-toidle-toaim.png)

> 若没有这两条横边，快速按下/松开右键仍会把整段过渡播完，手感「不跟手」。

### 转换规则详解：ToIdle → Move（含 OR Run）

这条边的完整逻辑：

```
允许从 ToIdle 切到 Move = (ToIdle 动画剩余时间 < 0.4)  或  (E Player State == Run)
```

| 节点 | 解释 |
|:---|:---|
| **Get Relevant Anim Time Remaining (ToIdle)**（绿色纯函数） | 获取源状态（ToIdle）正在播的动画还剩多少时间。括号里的 `(ToIdle)` 指定检测的是「源状态」动画的进度 |
| **`< 0.4` 比较**（红色布尔输出） | 过渡动画快播完才允许切走，防止动画才播个开头就被打断 |
| **E Player State `== Run`**（枚举判断） | 玩家当前是否在跑 |
| **OR**（布尔或） | 两个条件满足其一就放行 |
| **Result → Can Enter Transition** | 最终结果决定是否允许切换 |

**为什么要 OR Run**：松右键马上按跑步键时，角色状态早已是 Run，但动画会卡在 ToIdle 播完才走。加上 OR Run 后，跑步优先级高，强制立刻切换，不等动画——松瞄立刻 sprint 不卡。

## 第十步：Aim 节点配置（按速度混合 ADS Idle/Walk）

![Aim 节点配置](assets/img/l09-aim-state-config.png)

Aim 状态内部不播「一个」动画，而是**根据角色实际移动速度，在 Idle（稳瞄）和 Walk（走瞄）之间平滑切换**。相比纯状态机，这里用 **Blend Poses by Bone（按骨骼混合）** 节点做过渡，不会生硬跳切。

### 节点逐个解释（数据流从底到顶）

| 节点 | 解释 |
|:---|:---|
| **Character Movement**（深蓝，变量 Getter） | 从「我的变量」面板拖出的移动组件对象引用，后续从它身上取速度 |
| **Velocity**（深蓝针脚） | 从组件读当前帧的**速度向量（Vector）**。Target 脚接 Character Movement；输出一根蓝色细线，代表 (X, Y, Z) 三轴速度 |
| **Vector Length**（绿色纯函数） | 把蓝色速度向量变成绿色标量 float（模长，忽略方向）。站着不动 ≈ 0；走路 ≈ 200~400；跑步 ≈ 600+。无白色执行线 = 纯函数 |
| **`> 0.0` 比较** | 判断「速度是否 > 0」（在移动为 true），输出红色布尔线 |
| **Blend Poses by Bone**（核心混合节点） | True Pose 接 Walk（在动时播）、False Pose 接 Idle（静止时播）、True/False Blend Time 各 **0.1 秒**、Active Value 接「速度 > 0」的布尔。「by Bone」表示可指定某些骨骼用不同权重混合（默认全骨骼统一），高级用法可做「上身瞄准、下身走路」分层 |
| **两个 Animation Player**（Walk / Idle） | 直接引用 `.uasset` 动画资产，分别连 True / False Pose。**记得勾选循环动画** |
| **Output Animation Pose** | 这个状态的最终出口 |

### 数据流全景

```
Character Movement (组件)
    ↓ (深蓝对象线)
Velocity (取速度向量)
    ↓ (蓝色向量线)
Vector Length (向量 → 标量)
    ↓ (绿色 float 线)
[> 0.0] 比较
    ↓ (红色 bool 线)
Blend Poses by Bone.Active Value
    ├─ True  → Walk 动画 → True Pose
    └─ False → Idle 动画 → False Pose
    ↓ (混合后的姿势)
Output Animation Pose → 屏幕上的角色
```

### 与 Event Graph 的分工（重要）

| 位置 | 做什么 | 驱动数据 |
|:---|:---|:---|
| **Event Graph**（第 06 课） | 每帧算 `E Player State` 枚举 | **输入意图**（玩家是否按键：Move X/Y + Want to Run/Aim） |
| **AnimGraph**（本图） | 根据**实际速度**混合 Idle/Walk | **实际物理结果**（Character Movement.Velocity 长度） |

两者不完全一致，但这正是正确的分工：

- 按了 W 但被墙挡住 → 输入有、速度 = 0 → 逻辑说 Walk，视觉播 Idle（✅ 对）
- 松开按键但惯性滑行 → 输入无、速度 > 0 → 逻辑说 Idle，视觉播 Walk（✅ 对）

**结论**：Event Graph 管逻辑状态，AnimGraph 管视觉表现，各管各的。

> 枪械 `ABP_VIRTUL` 的 AnimGraph 与人物同理，注意连线，否则会出现动画不生效的问题。

## 易错点速查

1. **Update Animation 未接 Cast 执行针** → 混合空间始终中心 Idle。
2. Move X/Y 接混合空间时接反 → 前后与左右对调。
3. 用**数值等于**比较枚举 → 应用「等于/不等于（枚举）」；中文输入法敲 `！` 搜不到「不等于」。
4. 搜 `run` 找不到动画 → 搜 **`sprint`**。
5. Run / ADS 序列忘勾**循环动画** → 播一次就停；ToAim/ToIdle **勾了循环** → 永远进不了 Aim / 回不了 Move。
6. 只做手臂、漏枪；或两边平滑时间/过渡曲线不一致 → 穿模。
7. Event Graph 没同步 Character Movement → Aim 里的 Blend 布尔一直假，只会 Idle 瞄。
8. 忘了 ToIdle→Move 的 **OR Run** → 松瞄再 sprint 有明显延迟。
