## 本课要解决什么

1. 开课小坑：摄像机 **Use Pawn Control Rotation** 必须关掉（第 05 课已配，此处验证）。
2. **模块化**：`BP_WeaponBase` 父类 + 具体枪继承；从角色组件树删掉内嵌 Gun。
3. `SpawnWeapon` 函数：生成枪 Actor → Owner=玩家 → Attach 到 Arm。
4. Debug：部件 **NoCollision**（卡碰撞）、函数要在 BeginPlay 调用。
5. 枪械 ABP 重构：Initialize 里缓存人物动画蓝图引用；Update 时从**人物 ABP** 拉变量，避免人/枪不同步。

---

## 一、为什么要把枪拆出去

第 05 课把枪直接嵌在角色组件树里是为了快速预览，不符合扩展规范。拆成独立蓝图的目的是**解耦**：

| 点 | 含义 |
|:---|:---|
| 复用 | 新角色直接挂已有武器，不必每个角色重做枪逻辑 |
| 可维护 | 手感 / 后坐 / 伤害改枪蓝图即可，不牵动角色 |
| 扩展 | 新枪继承父类；角色侧尽量不改 |

一句话：**职责单一，改一块不影响另一块。**

## 二、枪械基类 BP_WeaponBase

位置：`Scripts/Weapon/Base`。类型：蓝图类-Actor。定义：枪械基类，保存枪械共有属性，例如子弹。

![SpawnWeapon 函数](assets/img/l10-spawnweapon-function.png)

### 节点逐个解释

| 节点 | 解释 |
|:---|:---|
| **SpawnActor BP_VIRTUS** | 在场景中生成枪械 Actor。**Spawn Transform 的 Location 要右键「分割结构体引脚」**——重组状态没有值，编译会报错 |
| **Owner → Self** | 要拉出 Owner 脚指向 self（玩家自身），否则后续枪械动画蓝图无法通过 Get Owner 找回角色 |
| **提升为变量 Weapon** | 把 SpawnActor 的返回值**提升为变量 `Weapon`**，方便后续引用生成的枪械实例——例如第 11 课瞄准时，头部骨骼要往枪械实例的插槽凑 |
| **Attach Actor to Component** | 注意是附加到**组件**（Parent = Arm），不是附加到 Actor；Location/Rotation/Scale Rule 用 Keep Relative |

> **坑**：函数写完不会自己跑。要在 **Event BeginPlay** 链上调用 `SpawnWeapon`（见[第04课](lesson-04.html)的 BeginPlay 图，最后一个节点就是它）。

## 五、枪械动画蓝图失效与重构（本课核心）

### 背景：拆出去后旧逻辑失效

枪拆成独立 Actor 后，枪械动画蓝图的 **Owning Actor 是 `BP_VIRTUS`**，不再是 `BP_FPS_Player`。第 07 课那套 `Try Get Pawn Owner → Cast To BP_FPS_Player` 直接失效；而且移动/状态变量都在角色蓝图里。

### 两个动画蓝图的关系（先理清对象）

| 动画蓝图 | 含义 | 角色 |
|:---|:---|:---|
| **ABP_FPSPlayer** | 人物动画蓝图 | **权威数据源**：从角色 Cast 拿到 Move X / Move Y / E_PlayerState / Character Movement，自己持有，**保持不变** |
| **ABP_VIRTUL** | 枪械动画蓝图（本课改它） | **复用者**：不直接 Cast 角色，而是引用 ABP_FPSPlayer，读它的变量驱动枪械动画 |

### 重构做了两件事

1. 把昂贵的**多层 Cast 链**从每帧的 `Event BlueprintUpdateAnimation` 挪到只触发一次的 `Event BlueprintInitializeAnimation`。
2. 上链把「人物动画蓝图 ABP_FPSPlayer 的引用」缓存成变量 `As ABP_FPSPlayer`，下链每帧直接复用这个引用读人物变量，不再重新 Cast。

重构后的 Event Graph：

![ABP_VIRTUL 重构后 Event Graph](assets/img/l10-abp-virtul-eventgraph-refactored.png)

### 完整上链（挂在 Event BlueprintInitializeAnimation，只跑一次）

> 这是**枪械 ABP_VIRTUL** 的初始化事件，目标是拿到**人物动画蓝图 ABP_FPSPlayer** 的引用。

```
Event BlueprintInitializeAnimation   ← 枪械动画蓝图初始化时触发一次（类似 BeginPlay）
  ↓
Try Get Pawn Owner                   ← 获取拥有此枪械动画蓝图的 Pawn
  ↓
Get Owning Actor                     ← 从 Pawn 取得其拥有者 Actor；输出连到下方 Cast 的 Object 引脚
  ↓
Cast To BP_VIRTUS                    ← Object 脚接 Get Owning Actor；确认是枪械蓝图类型
  ↓
Get Owner                            ← 从 BP_VIRTUS 拿回它的 Owner（即生成它的玩家）
  ↓
Cast To BP_FPS_Player                ← 转成具体的角色蓝图；唯一目的：拿到它下面的 Arm 变量
  ↓
Arm                                  ← 【关键】BP_FPS_Player 自身定义的变量（手臂骨骼网格体组件）；
                                       Cast 输出（As BP FPSPlayer）直接连到这个变量的 Target 引脚
  ↓
Get Anim Instance                    ← Target 接的是 Arm（骨骼网格体），不是角色本身；
                                       Arm 上挂载的正是人物动画蓝图 ABP_FPSPlayer
  ↓
Cast To ABP_FPSPlayer                ← 转成「人物动画蓝图」具体类型
  ↓
SET → 存为变量 As ABP_FPSPlayer      ← 缓存「人物动画蓝图引用」，供下链每帧复用
```

### 为什么 Cast To BP_FPS_Player → Arm 这一步不能漏

`Get Anim Instance` 是 **SkeletalMeshComponent 的函数**——它的 Target 脚必须接一个**骨骼网格体**，不能直接接角色 Actor。而人物动画蓝图 `ABP_FPSPlayer` 正是挂在角色蓝图的 **`Arm` 变量**（手臂骨骼网格体）上的。所以必须先 Cast 出角色 → 取出 `Arm`（**这就是这次 Cast 的唯一目的**）→ 再调 `Get Anim Instance`。

### 完整下链（挂在 Event BlueprintUpdateAnimation，每帧跑）

```
Event BlueprintUpdateAnimation       ← 每帧触发（类似 Tick）
  ↓
As ABP_FPSPlayer（上链缓存的人物动画蓝图引用，直接拖出来用）
  ├─ 读 Move X            → SET Move X
  ├─ 读 Move Y            → SET Move Y
  ├─ 读 E_PlayerState    → SET E_PlayerState
  └─ 读 Character Movement → SET Character Movement
```

下链**不再各自走一遍 Cast 链**，整张图 Cast 链只执行一次。枪械因此与人物**共用同一份变量**。

### 两个事件的根本区别

| 事件 | 触发频率 | 等价物 |
|:---|:---|:---|
| `Event BlueprintInitializeAnimation` | **只一次**（动画蓝图初始化时） | 类似 BeginPlay |
| `Event BlueprintUpdateAnimation` | **每帧**（动画更新时） | 类似 Tick |

### 重构的真正目的（FPS 语境）

**① 性能层**：多层 Cast（Get Owner + Arm + Get Anim Instance + 两次 Cast）有开销。旧版放每帧 Update 里每帧重转，浪费；新版挪到 Initialize 只执行一次，之后每帧零 Cast。

**② 业务层（FPS 特有，本质原因）**：第一人称里，**手臂骨骼和枪械骨骼要使用同一份变量**。如果枪械每帧自己重新 Cast、重新同步，引擎会在「枪械的变量」与「人物的变量」之间频繁切换调用，后果是：手臂和枪的动作**同步失败**（父子挂载错位、枪跟不上手）、动作**卡顿/抖动**。

把人物动画蓝图引用在初始化时一次性锁定、每帧只更新变量值，就能保证枪械与人物**始终从同一份变量（ABP_FPSPlayer 持有）驱动**，同步稳定、动作流畅。

### 两版对比

重构前（旧版，单链、每帧 Cast 角色）vs 重构后（新版，双事件、初始化缓存）：

![对比 1](assets/img/l10-abp-virtul-compare-1.png)

![对比 2](assets/img/l10-abp-virtul-compare-2.png)

## 六、附：Cast To 概念补充

### Cast To 是什么意思

`Cast To` 是 UE 的**类型转换**节点。它把一个「泛化」的对象引用精确成「具体的子类类型」，这样才能访问该具体类型才有的成员。

**类比**：街上看到一只 `Animal`（动物），动物不会「写代码」。但当你确认它其实是 `Programmer`（程序员），就可以让它写代码。这个「确认它是程序员」的动作，就是 `Cast To Programmer`。

这本质是**面向对象继承的向下转型（downcast）**：`Pawn` 是父类，`BP_FPS_Player` 是子类。父类引用看不到子类新增的成员，除非向下转型。

### 为什么需要这么多 Cast To

因为引用是**一层层往下拿**的，每层返回的都是「更泛的类型」，必须逐个 Cast 才能往下挖。每个 Cast 都在「解锁下一层的专属能力」：

| Cast 节点 | 输入来源 | 输出用途 | 解锁的是什么 |
|:---|:---|:---|:---|
| `Cast To BP_VIRTUS` | Get Owning Actor | → Get Owner.Target | 确认是枪械蓝图类型，才能调它的 Get Owner |
| **`Cast To BP_FPS_Player`** | Get Owner | **→ Arm.Target** | 确认是角色蓝图类型，**才能取出它下面的 Arm 变量** |
| `Cast To ABP_FPSPlayer` | Get Anim Instance | → SET 缓存 | 确认是人物动画蓝图类型，才能缓存引用供下链复用 |

### 风险：Cast 可能失败

如果运行时对象其实不是目标类型，整条链会**静默断掉**。每个 Cast 节点都有 `Cast Failed` 白色执行输出分支——正规做法是接个 `Print String` 调试，确认线上不会静默失败。

### 前提与注意事项

- **前提**：角色 / 动画蓝图对应关系在运行期稳定（单机 FPS demo 一般成立）；若游戏里会动态换角色 / 切换 Pawn，「只 Cast 一次」会拿到过期引用，需要在 `On Possessed` 之类事件里重新 Cast。
- **命名容易看混**：`As ABP_FPSPlayer` 这个变量在**枪械**蓝图里，但它存的是**人物动画蓝图的引用**（不是枪械自己）。这是 Cast 节点输出脚的默认名字，工程里保持原样即可——看到它时记住"这是人物的 ABP"就行。

## 易错点速查

1. Camera **Use Pawn Control Rotation** 忘关 → 晃动不对。
2. Spawn Transform 未分割 → 编译报无效；分割成默认 0 即可。
3. 写了 `SpawnWeapon` 却没在 BeginPlay 调用 → 场景里没枪。
4. Owner 未设为 Self → 枪械 ABP `Get Owner` 拿不到玩家。
5. Attach 点错「附加到 Actor」（应是附加到组件）。
6. 枪械部件有碰撞 → 和角色胶囊互卡，方向失灵。
7. 枪械 ABP 仍每帧 Cast / 仍直接读 Player → 性能差或动画不同步。
8. 两套 ABP 都要改完再狂按瞄准验证。
