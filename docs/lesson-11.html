第11-12课 · 完善瞄准系统（上/下）

▶ 对应视频（P13）

对应视频：P12（第 11 课·上）、P13（第 12 课·下）。两课内容合并成一页。

本课要解决什么

上：头部平移瞄准

  1. 在枪骨骼 body 上加 AimSocket 插槽，定位瞄准时头部应凑到的位置。
  2. 父类 BP_WeaponBase 提供 getAimSocketLocation 函数（子类自动继承）。
  3. 角色 SpawnWeapon 缓存 Weapon 引用；人物 ABP 每帧取插槽位置。
  4. AnimGraph：缓存 Basic 姿势 → 按 E_PlayerState 混合；Aim 时用 Transform (Modify) Bone 把 Head 移到插槽。
  5. Debug：ABP 初始化早于武器生成，Weapon 可能为空 → 用 Is Valid 护住。

下：机瞄 + 准星 + FOV 过渡

  1. 在 BP_VIRTUS 里加 Sight 机瞄组件，让枪械有近距离瞄具。
  2. 修复全息瞄准镜准星在快速移动时被动态模糊拉成长条。
  3. 瞄准时摄像机 FOV 从默认 105 平滑缩到 75，松开右键时平滑恢复。
  4. 把默认 FOV 存成变量 DefaultFOV，开局调用 UpdateDefaultFOV 初始化。

第一步：在枪骨骼上加 AimSocket

找到 BP_VIRTUS，在右侧骨骼网格体资产找到枪械主体，双击进入骨骼编辑：

在右侧 body 骨骼上右键添加插槽，重命名 AimSocket，并调整相对位置。这一步的作用是定位：瞄准时让头能伸到这个位置。

第二步：父类函数 getAimSocketLocation

写在 BP_WeaponBase（不要只写在 Virtus 子类，以后每把枪都能用）：新建函数，拖出 Weapon 组件 → Get Socket Location，Socket Name = AimSocket（建议从插槽名复制粘贴防打错）。函数把插槽位置返回为变量 AimSocketLocationReturn——注意这是世界空间坐标。

第三步：验证子类继承

在 BP_VIRTUS 中点击「函数-重载」，可看到 getAimSocketLocation，说明创建成功：

第四步：SpawnWeapon 提升 Weapon 变量

在 BP_FPS_Player 的 SpawnWeapon 函数中，把 SpawnActor BP_VIRTUS 的返回值提升为变量 Weapon（第 10 课已做），供动画蓝图访问该武器实例并取到插槽位置。

第五步：ABP_FPSPlayer Event Graph 取插槽位置

在已有的 Cast 玩家之后：GET Weapon → 调用 getAimSocketLocation → SET 存进变量 AimSocketLocationReturn。

别被显示名迷惑：这个变量在蓝图里显示成 Aim Socket Location Return（UE 会在大写字母之间自动加空格显示）。它和 AimSocketLocationReturn 是同一个变量，不是两个。同理，E_PlayerState 的类型会显示成 E Player State。

注意 Is Valid 节点：整个流程执行顺序有先后——动画蓝图初始化很早，SpawnWeapon 可能在后几帧才给 Weapon 赋值。Is Valid 可以检测 Weapon 变量是否为空，仅 Valid 时才调函数，否则退出 PIE（Play In Editor，编辑器内运行）时会报「尝试读取 Weapon 时结果为无（Accessed None）」。

第六步：ABP_FPSPlayer AnimGraph 改头部骨骼

实现的功能

瞄准时，让角色的头部骨骼（Head）平移到枪械 AimSocket 插槽所在的世界坐标位置，实现「探头瞄准」的视觉效果；不瞄准时恢复原位。两者以 0.2 秒平滑过渡。

核心思路：不是单独做一套 Aim 动画，而是用 Transform (Modify) Bone 程序化地把 Head 骨骼「搬」到枪械上预留的 AimSocket 插槽位置。

数据流全景

                    AimSocketLocationReturn（= AimSocket 世界坐标）
                           ↓ Translation
Use cached pose 'Basic'         ↓
    ↓                      Transform (Modify) Bone ← Bone to Modify = Head
    ↓ Local To Component          ↓
    ↓                        Component To Local
    ↓                              ↓
    │                         Aim Pose（瞄准姿态：头部已偏移）
    │                              │
    │    Use cached pose 'Basic'   │
    │        ↓                     │
    │    Default Pose（原始姿态）   │
    │        │                     │
    └───────┼─────────────────────┘
            ↓
    Blend Poses (E:PlayerState)    ← E_PlayerState 枚举控制切换
            ↓ Result
       Output Pose → 屏幕上的角色

两条路径共用同一份 Basic 缓存：一路保持原样 → Default Pose（不瞄准：头部不动）；一路经过 Modify Bone 改了 Head 位置 → Aim Pose（瞄准：头部凑到枪前）。

节点逐个解释

节点 解释
Use cached pose 'Basic'（出现两次） 取出之前用 New Save cached Pose 保存的 Basic 状态机快照（状态机内部即第 07–09 课搭的 Move/Run/Aim 那套）。为什么用缓存：Basic 的姿势被用了两次（一路 Default、一路 Aim），缓存只算一次状态机，省性能
Local To Component（引擎自动创建） 把 Use cached pose 'Basic' 连到 Transform (Modify) Bone 时，虚幻自动插入的「胶水」节点（非手工摆放），把姿势从骨骼本地空间转到组件空间，以匹配 Modify Bone 的工作空间
Transform (Modify) Bone ⭐ 核心节点 参数见下表。它在做的事：把 Head 骨骼从默认位置「搬」到 AimSocket 插槽所在位置，玩家看起来就像把头凑到枪前瞄准
Component To Local（引擎自动创建） 把 Modify Bone 的输出连回 Blend Poses 的 Aim Pose 脚时引擎自动插入，把改完的姿势从组件空间转回骨骼本地空间
第二个 Use cached pose 'Basic' 和第一个是同一份缓存的不同引用，直接作为 Default Pose（不瞄准时的原始姿态）
Blend Poses (E:PlayerState) ⭐ 状态混合 右键节点「添加元素引脚 Aim」——只加 Aim，因为这里是瞄准动作；Default/Aim Blend Time 都设 0.2 秒，让探头/缩头过渡舒缓；Active Enum Value 接 E_PlayerState
Output Pose AnimGraph 最终出口，混合后的结果就是角色每帧实际渲染的姿势

Transform (Modify) Bone 参数

参数 值 含义
Bone to Modify Head 要修改的目标骨骼
Translation 接 AimSocketLocationReturn 头部要平移到的目标位置 = AimSocket 世界坐标
平移模式 Replace Existing（替换现有项） 直接用目标位置替换 Head 原位置
平移空间 World Space（世界场景空间） 因为 getAimSocketLocation 本身就是基于世界场景空间返回坐标，必须同空间才能对齐
Rotation (0,0,0) 不旋转
Scale (1,1,1) 不缩放

设计亮点

  1. 不需要美术做额外的 Aim 动画——只需一个 AimSocket 插槽位置 + 程序化移动 Head 骨骼。
  2. 换枪也通用——不同枪只要 AimSocket 位置不同，头部自动凑到不同位置。
  3. 过渡平滑——0.2 秒 Blend 时间让探头/缩头很自然。

第七步：给枪加机瞄 Sight

在 BP_VIRTUS 的组件树中新增一个 Static Mesh 组件，命名为 Sight，放到 Weapon 下合适的位置（常在 Scope 与 Stock 之间）。为该组件指定铁瞄 / 备用瞄具模型，并挂到对应插槽上。

注意：这是枪械的额外瞄具，和下面的 Scope（全息镜）是两套东西。Sight 用于近距离机瞄；Scope 上的准星问题是下一步要修的。

第八步：修复快速移动时准星被拉成长条

全息镜的中间准星用的是一张发光贴图（准星纹理）。在快速移动时，场景被引擎加了动态模糊（Motion Blur），半透明材质也会跟着一起模糊，导致准星变成一条长矩形。

1. 打开全息镜材质

选中 Scope 组件 → 找到其材质槽里带准星的元素（通常元素编号旁会显示 M_Holographic_Inst6 之类的实例材质）→ 双击进入。

在材质实例里看到它的父项是 M_Holographic，继续双击父项进入基础材质。

2. 改半透明通道为“动态模糊后”

在材质图表左侧的**细节（Details）**面板里：

  • 确认混合模式 / 着色模型是半透明（Translucent）（准星要透光 / 叠加显示）
  • 展开**高级（Advanced）**分组
  • 找到半透明相关的通道设置，把它改成 After Motion Blur（中文显示为 “动态模糊后”）

为什么这样改

引擎默认会把半透明物体也纳入动态模糊计算。After Motion Blur 的意思是：先对整个场景做完整动态模糊，最后再渲染这个材质。这样准星就不会被拉长，而是始终清晰。

第九步：瞄准时摄像机 FOV 平滑缩放

基础概念：FOV

FOV = Field of View（视场 / 视野），数值越小画面越窄、像望远镜 / 瞄具拉近；数值越大画面越广、有速度感。

本项目默认值：105（广角，日常 / 跑步时带感）；瞄准时缩到：75（收窄，更聚焦）。

实现位置

整个 FOV 过渡写在 BP_FPS_Player 的事件图表里，起点是 Enhanced Input Action IA_Aim（不是 Update Animation 之类的每帧事件）。

三条链路，逐个解释

链路 1：按住右键 → 平滑拉近到 75

IA_Aim.Triggered
  ↓
SET Want To Aim = true（顶部，带 ✓）
  ↓
Get World Delta Seconds（绿 float，帧间隔）
  ↓                              ↘
Camera                         FInterp To
  ↓                                ├ Current    = Get Field Of View(Camera)
Set Field Of View                │ Target     = 75
  ├ Target = Camera              │ DeltaTime  = Get World Delta Seconds
  └ Value  = FInterp To 输出 ────┘ Interp Speed = 8
  ↓
Clear and Invalidate Timer by Handle（清掉恢复定时器）
  • FInterp To：每帧把 Camera.FOV 从当前值向 75 逼近；Interp Speed = 8，越大过渡越快。
  • Clear and Invalidate Timer by Handle：把链路 2/3 启动的“恢复 FOV 定时器”停掉，防止按下瞄准时新旧两个过渡互相打架。

链路 2：松开右键 → 启动恢复定时器

IA_Aim.Completed
  ↓
SET Want To Aim = false（底部，无 ✓）
  ↓
Set Timer By Event
  ├ Event        = OutFOV（自定义事件，见链路 3）
  ├ Time         = Get World Delta Seconds（≈ 每帧触发一次）
  ├ Looping      = ✅ 勾选
  └ Return Value = Handle（存成变量 OutFOVHandle，供后面停止用）

链路 3：自定义事件 OutFOV → 平滑恢复到默认 FOV

OutFOV（自定义事件）
  ↓
Get World Delta Seconds
  ↓                              ↘
Camera                          FInterp To
  ↓                                ├ Current    = Get Field Of View(Camera)
Set Field Of View                │ Target     = DefaultFOV（变量 = 105）
  ├ Target = Camera              │ DeltaTime  = Get World Delta Seconds
  └ Value  = FInterp To 输出 ────┘ Interp Speed = 8
  ↓
Nearly Equal (Float)
  ↓（A = 当前 FOV，B = DefaultFOV，Error Tolerance = 0.1）
Branch
  ├ True  → Clear and Invalidate Timer by Handle（已恢复，停定时器）
  └ False → 下帧定时器继续触发 OutFOV
  • Nearly Equal：判断当前 FOV 与默认 105 的差值是否小于 0.1，到了就停止，省得无限跑。
  • DefaultFOV 是下一节（第十步）才存的变量，这里先当已知值 105 看。

关键常量确认表

参数 值
瞄准时 FOV 目标 75
默认 FOV 105

第十步：把默认 FOV 存成变量

让恢复链路能读到“当前默认 FOV”，不要把 105 写死，所以建一个变量 DefaultFOV，开局时从摄像机的 Field Of View 里读一次。

1. 新建 UpdateDefaultFOV 函数

  • 函数内：Camera → Get Field of View → SET DefaultFOV
  • 这个函数只负责一件事：把摄像机的当前 FOV 复制到变量 DefaultFOV

2. 在 Event BeginPlay 里调用

在 Event BeginPlay 链的末尾接上 UpdateDefaultFOV（常在 Add Mapping Context 和 SpawnWeapon 之后）。游戏开始时摄像机已经按场景配置好了 FOV，执行一次即可得到默认值。

易错点速查

  1. 插槽名拼错 → Get Socket Location 退回组件原点，头会漂。
  2. Modify Bone 用组件空间而非世界空间 → 对不齐。
  3. 平移模式未设 Replace Existing。
  4. 函数写在 Virtus 子类而非 WeaponBase → 每把枪重写一遍。
  5. Spawn 后未缓存 Weapon / ABP 未 Is Valid → 运行时报空（Accessed None）。
  6. 忘了给枚举混合加 Aim 姿势脚，或 Aim 支路没接 Modify Bone。
  7. 以为 Local To Component / Component To Local 要手工添加——它们是引擎连线时自动插入的。
  8. 第七步给枪加 Sight 时和 Scope 混淆，挂到错误插槽 → 模型位置不对。
  9. 第八步修复准星只改了材质实例、没改父项材质 → 重新进游戏还是会被动态模糊拉长。
  10. 第九步 FOV 过渡没清掉恢复定时器 → 按住瞄准时和恢复链路“打架”，FOV 抖动。
  11. 第九步 Set Timer By Event 没勾选 Looping，或没存 Handle → 恢复 FOV 只执行一帧。
  12. 第十步 DefaultFOV 写死成 105 而不调用 UpdateDefaultFOV → 以后改摄像机 FOV 时恢复值会错。
